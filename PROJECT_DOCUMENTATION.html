01The problem

Why a text-only classifier is structurally unable to solve this.

Fraudulent investment promotions hide their claim inside the image. A doctored profit-and-loss screenshot, a chart with a truncated axis, a pasted SEBI or RBI logo, a borrowed photograph of a known finance personality — the deceptive assertion is carried by pixels. The visible caption stays vague and harmless: "Check this out", "DM for details".

A text-only classifier sees only the harmless half. That is not a tuning problem; the signal is not present in its input at all. This is the gap the project targets.

Three modalities

#ModalityWhat it contributesEncoderPhase
1ImageVisual manipulation, forged logos, chart distortionViT / CLIP2
2TextCaption plus OCR of in-image text, code-mixed Hindi/EnglishMuRIL / IndicBERT2
3PropagationHow a post travels channel to channel on TelegramGNN (PyG)3

A cross-attention layer fuses them. An ablation comparing text-only, image-only and fused models measures what each modality actually contributes, rather than assuming it.

Empirical support

The investigation in §03 found that the dominant Indian fraud pattern in 2024–26 is deepfake celebrity endorsement — a public figure appearing to promote an investment platform. In every such case the caption is innocuous and the deception lives entirely in the video frame. That is direct evidence for the multimodal premise, not just an assumption.

02System design

Layered by pipeline stage, with one shared data contract.

The system is organised as a linear pipeline. Each stage reads the previous stage's output, writes its own, and is independently resumable. Every stage speaks the same record type, so adding a source or an encoder never requires touching the stages around it.

Repository layout

Minor Project/ ├── PROJECT_DOCUMENTATION.html this file ├── pyproject.toml installable package; extras per phase ├── README.md ├── configs/sources.yaml every tunable parameter, no magic numbers in code ├── src/fipd/ │ ├── schema/ records.py the shared contract │ ├── collection/ base · wordpress · │ │ article · googlefactcheck · registry │ ├── enrichment/ ocr.py · translit.py │ ├── curation/ finance_filter · labels · │ │ dedup.py · splits.py │ ├── datasets/ (Phase 2) │ └── utils/ http · io · logging_setup ├── scripts/ 01_collect · 02_enrich_images · 03_ocr · │ 04_curate · 05_split · calibrate_dedup ├── tests/ unit/ · integration/ · fixtures/ · run_all.py ├── docs/ CHECKLIST.md · PHASE0_GUIDE.md └── data/ gitignored — large and re-derivable

Why this shape

  • Stage numbering in scripts/ makes the execution order unambiguous. A new team member can read the directory listing and know what runs when.
  • One package, layered by stage rather than by file type. Adding an OCR backend touches one directory; adding a source touches one directory.
  • Installable via pyproject.toml, so imports are real imports rather than sys.path manipulation. Optional extras ([ocr], [model], [graph], [serve]) keep a Phase-1 install from pulling in torch.
  • Config over constants. Thresholds, sources, seeds and ratios live in YAML. Every number that affects a result is visible in one file and quotable in the report.
  • Thin scripts, thick library. The CLIs parse arguments and print reports; all logic sits in src/fipd/ where it can be unit-tested.

03Investigation

What the data sources actually look like, measured rather than assumed.

Before writing any scraper, each proposed source was probed for its robots.txt, a structured API, a sitemap, embedded structured data, and — most importantly — its actual yield on finance queries. Several assumptions in the original proposal did not survive.

A keyword search for investment across the entire Alt News archive returned three articles, none about investment fraud. Alt News stays in the config for coverage, but expecting volume from it would be a planning error.

BOOM Live is the primary source

BOOM runs a dedicated ScamCheck vertical plus a fact-check/business section covering investment fraud, fake celebrity endorsements, crypto scams and fraudulent trading apps. This was not in the original proposal, which treated all four fact-checkers as roughly equivalent. Newschecker labels its own finance content

Newschecker prefixes financial debunks with "Scam Alert!" — a free high-precision filter. A search for investment returned 10 posts, 5 directly on-target, all of the same shape:

  • "Fake Indian Express Report On Ajit Pawar Entrusting AI-Based Investment Platform To Family"

Design change from this investigation

Every serious fact-checker publishes schema.org ClaimReview markup — the structured data Google reads to build fact-check panels — and Google indexes all of it behind a free API. That became the primary discovery layer: one query surface returning claim text, the publisher's own verdict, language and URL across every publisher at once, instead of five HTML parsers that break on redesign.

The API also supports reviewPublisherSiteFilter, so collection runs a publisher sweep across nine Indian fact-checkers — pulling entire archives and letting the finance filter narrow them — before falling back to a keyword sweep. That does not depend on our lexicon matching their headline wording, which materially raises recall.

04Design decisions

Each one had a plausible alternative. Stating what was rejected, and why, is the defensible form.

Google Fact Check API as the primary discovery layer

Rejected
Crawling each fact-checker's HTML independently.
Why
Five HTML parsers means five things that silently break on redesign. ClaimReview is a standard publishers maintain themselves, because their Google visibility depends on it — a strong incentive for accuracy, which is exactly what you want in a label source.
Cost
The API returns no images. Stage 02 exists to fetch them.

"Misleading" maps to FAKE, not to a third class

Rejected
A three-class problem: true / misleading / false.
Why
A truncated-axis chart is factually "partly true" and is still a fraudulent promotion. For a fraud detector the operative question is does this deceive, not is every pixel false. Binary also keeps class counts usable at the sizes this dataset will reach.
Unresolved
Verdicts that cannot be placed map to unknown and are held out of training rather than guessed at — guessing injects label noise no model capacity recovers from.

Finance relevance is a hand-weighted lexicon, not a classifier

Rejected
Training a small text classifier to identify finance content.
Why
At collection time there are no labels to train it on — the argument is circular. And a transparent rule can be inspected, tuned and defended in a viva.
How
Terms weighted 3.0 / 1.5 / 0.7; fields multiplied (title ×2.5, claim ×2.0, image text ×1.5, body ×1.0). A headline term counts far more than a passing mention in paragraph nine.
Key part
The negative lexicon. Political stories say "crore", "scam" and "fraud" constantly. Terms like communal, election, temple subtract from the score. In testing, a communal-riot article mentioning "crores of views" scored −4.0 against a keep threshold of 4.0, while a genuine SEBI trading-app scam scored 70.15.
Scripts
English, Devanagari (निवेश घोटाला) and romanised Hinglish (paisa double) — scam creatives routinely use Latin-script Hindi, and a Devanagari-only lexicon would miss them entirely.

Three perceptual hashes, not one

Problem
Exact SHA-256 hashing does not find duplicates: each fact-checker re-hosts the creative through its own CDN, which re-encodes and often re-crops it.
Built
pHash (low-frequency DCT, most robust to compression), dHash (brightness gradients, robust to rescaling), cHash (colour block signature). Combined into one weighted normalised distance.
Why colour
pHash and dHash both work on greyscale and are blind to colour. Two creatives from the same template with different branding collide under both. Scam creatives are mass-produced from templates, so this is a live failure mode — it was found by a test, not anticipated.
Threshold
Deliberately not hardcoded from synthetic data. scripts/calibrate_dedup.py estimates it from the real corpus. The shipped default is a starting point, and this is stated in the code.

Over-merging is the safe direction

Insight
The two dedup failure modes are not symmetric.
Over-merge
Two distinct items land in one cluster. Costs a little data diversity. Cannot cause leakage.
Under-merge
Duplicates land in different clusters, the same creative appears in train and test, and every metric is silently inflated.
Therefore
The clustering default errs liberal; pick_canonical uses a stricter threshold, because there the asymmetry runs the other way.

Split by claim cluster, never by record

Why
This is the most common silent failure in misinformation-detection work, and it is invisible in the metrics: leakage makes results better, so nothing looks wrong.
Defence
verify_no_leakage asserts every cluster lives entirely in one split, stage 05 refuses to write the manifest if it fails, and the test suite injects deliberate leakage to confirm detection fires.
Also
Stratified by (label, source) so no split is accidentally single-publisher — otherwise the test set measures one newsroom's house style rather than fraud.
Reproducibility
Seeded RNG over sorted cluster ids. The manifest records the seed, counts and a hash; every result should cite that hash.

Image hygiene — the most likely source of a fake result

The trap
Fact-checkers stamp verdict graphics onto the images they debunk. If those enter training, the model learns to detect the watermark, not the fraud — and reports excellent accuracy while being worthless on real posts.
Defences
(1) URL blocklist for logos, avatars, share icons. (2) ImageAsset.role="annotated" tagging for suspected verdict stamps. (3) Extraction scoped to the article body, so sidebar thumbnails never enter. (4) OCR skips annotated images, so the word "FALSE" never reaches the text branch.
Insufficient
None of this replaces a manual spot-check before training. Stated in the README and the checklist.

OCR text goes first in the text input

Why
The claim being classified lives inside the image. When the tokeniser truncates at max length, it should eat the caption, not the thing we care about.
Also
Which fields are included (caption-only / OCR-only / both) is itself an ablation axis worth reporting.

Transliteration by curated lexicon, not blanket conversion

Problem
MuRIL was pretrained on Devanagari Hindi and English, but not on romanised Hindi at scale. "paisa double" tokenises into English-looking subwords carrying none of the Hindi meaning.
Rejected
Transliterating everything. Romanised Hindi has no standard orthography ("paisa"/"paise"/"paisaa"), and rule-based conversion of genuinely English words produces nonsense.
Built
A curated domain lexicon (~70 finance/scam terms) with optional library fallback. Both surface forms are kept by default — the encoder uses whichever it represents better, at the cost of sequence length only.

05Module reference

What each file does and the non-obvious parts of how.

schema

FileResponsibility
records.pyFactCheckRecord and ImageAsset — the contract every stage speaks. The uid property (SHA-1 of source:source_id) is what makes every stage resumable: stable across re-runs, unique across sources.

collection

FileResponsibility
base.pyShared machinery. extract_images() is the intricate part: reads data-src/data-lazy-src before src so lazy-loaded images are not missed, parses srcset and picks the widest variant (OCR needs legible text; the default src is often a 300px thumbnail), resolves relative URLs, captures alt and <figcaption>, tags suspected verdict stamps.
wordpress.pyWP REST API. Search mode and category mode; caches the category map; unescapes HTML entities; puts the featured image first because on fact-check sites the hero is very often the viral creative itself.
article.pySitemap discovery (recursing into indexes, filtering by path) plus ClaimReview JSON-LD parsing, walking @graph arrays. Falls back to NewsArticle, then Open Graph, then <title>.
googlefactcheck.pyTwo-pass sweep: publisher filter across nine Indian fact-checkers, then keyword queries. One API claim can carry several publisher reviews; each is emitted separately, which is correct — they are independent labelled items with different articles and images.
registry.pyBuilds scrapers from YAML. Adding a WordPress or sitemap source needs no code change.

enrichment

FileResponsibility
ocr.pyThree backends (PaddleOCR / EasyOCR / Tesseract) behind one OCREngine interface, imported lazily so this module never drags in torch. Results carry a script_profile (Devanagari / Latin / digit proportions) and a looks_like_garbage() quality gate. A disk cache makes the slowest stage resumable; engine failures return an error result rather than raising.
translit.pyNFC normalisation (Devanagari has multiple encodings for the same visible character), the romanised-Hindi lexicon, code-mixing detection, and build_text_input() which assembles the text branch's input.

curation

FileResponsibility
finance_filter.pyThe weighted lexicon and negative lexicon, plus DISCOVERY_QUERIES — so the project's whole finance vocabulary sits in one file.
labels.pyOrdered verdict-string rules ("Mostly True" must be checked before generic false patterns), English and Devanagari, with a title-convention fallback for sources that emit no rating.
dedup.pypHash / dHash / cHash, combined distance, union-find single-linkage clustering, and text-shingle Jaccard for creatives that differ visually but assert one claim. pick_canonical selects one representative per cluster deterministically.
splits.pyGroup-aware stratified splitting with largest-remainder allocation (so small strata do not lose their val/test share to floor()), the leakage assertion, and manifest save/load.

utils

FileResponsibility
http.pyRate limiting measured from the last request (so slow responses do not stack extra delay), retry with backoff honouring Retry-After, and disk caching that stores headers separately — WordPress returns pagination totals in X-WP-TotalPages, and losing that on a cache hit would break paging.
io.pyJSONL read/write, bad-line tolerance, existing_uids() — the basis of every resume.
logging_setup.pyOne logging config; silences urllib3/PIL, which drown real output at DEBUG.

Scripts

python scripts/03_ocr.py --backend easyocr   # extract in-image text

Method: a local mock, not the live sites

tests/fixtures/mock_server.py replicates the real response shapes — WordPress pagination with genuine X-WP-Total headers, a sitemap with <lastmod>, article pages carrying real ClaimReview and NewsArticle JSON-LD, and valid JPEG bytes. Field and header names were verified against the live endpoints during the investigation, so a scraper that passes here exercises the same code paths it will use in production — without hammering small non-profit newsrooms during development, and without tests that break whenever a site changes.

Fixtures are adversarial on purpose

  • A srcset where the correct answer is not the default src
  • A lazy-loaded image with no src at all
  • A site logo and a verdict stamp that must both be excluded
  • A sidebar "related story" thumbnail that must not enter the record
  • A communal-riot article containing "crores" — the false-positive trap the negative lexicon exists to catch
  • Deliberately injected split leakage, to confirm the detector fires

Image tests use real transforms

Synthetic creatives are generated with PIL and then genuinely re-compressed (JPEG q25), rescaled (50% and 2×), cropped and brightened. The whole point of perceptual hashing is surviving exactly those operations, so a mock would prove nothing.

The assertion that matters is threshold-independent: every true duplicate must be closer than every distinct pair. Absolute thresholds are data-dependent and are calibrated separately.

A test that found a real bug

The "distinct images are not merged" assertion failed during development: two different creatives hashed 6 bits apart, under the threshold. Diagnosis showed all collisions were same-template pairs — and since pHash and dHash both operate on greyscale, they were blind to the colour differences that distinguish them. That is what motivated adding cHash. The failure came from a test, not from foresight.

07Open problems

The honest limitations. Both are better raised with the supervisor now than discovered in the final month.

Problem 1 — yield

The archives may not contain enough finance items to train on. Alt News has 11 finance posts against 4,157 political ones. Run scripts/04_curate.py and read the yield table before committing to the current phasing.

If the count lands under ~500, the fact-check archives are a seed and evaluation set, not a training set, and Telegram collection has to move from Phase 3 up to Phase 1 — Telethon on public channels is then the only route to training-scale data. This is a scheduling risk, not a fatal one, but it needs deciding early.

Problem 2 — class balance (the serious one)

Every record this pipeline produces is labelled fake. Fact-checking archives exist to document falsehoods; nobody publishes an article confirming that an ordinary legitimate advertisement is legitimate. A binary classifier cannot be trained on one class. Stage 04 prints an explicit warning when it detects this.

Legitimate promotions must be sourced separately. Candidates:

  • SEBI-registered investment advisors' public posts — the registry of registered IAs and RAs is public, so the label is externally defensible
  • AMFI "Mutual Funds Sahi Hai" campaign creatives
  • Registered broker marketing — Zerodha, Groww, Upstox
  • RBI / SEBI investor-education material
  • Legitimate financial news graphics — hard negatives that resemble the fake charts but are not fraudulent

The critical constraint: negatives must be the same genre of image — promotional finance graphics — differing only in whether they deceive. A model trained on scam creatives versus random stock photos will report 97% accuracy and will have learned to recognise a screenshot, not a fraud. This is the highest-risk decision in the project, and it matters more than the choice of image encoder or fusion mechanism.

Things to get right in Phase 2

  • Build the ablation arms first. Text-only and image-only baselines are the deliverable the supervisor asked for, not an appendix — and they give a working number early.
  • Report precision, recall, F1 and PR-AUC, not accuracy. Accuracy is close to meaningless on imbalanced fraud data.
  • Run the targeted experiment. Build an evaluation subset where the caption is benign and the claim is image-only. If fusion does not beat text-only there, the central thesis is not demonstrated regardless of overall F1. This is the most convincing single experiment available.
  • Define "lightweight" as a number before building — model size, CPU latency, parameter count — so Phase 4 measures against a commitment rather than reverse-justifying a result.
  • 3–5 seeds per arm, reporting mean ± std. A 1% gain on one seed is noise.
