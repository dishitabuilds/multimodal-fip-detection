01The problem

Why captions alone can miss the claim carried by an image.

Fraudulent investment promotions hide their claim inside the image. A doctored profit-and-loss screenshot, a chart with a truncated axis, a pasted SEBI or RBI logo, a borrowed photograph of a known finance personality — the deceptive assertion is carried by pixels. The visible caption stays vague and harmless: "Check this out", "DM for details".

A caption-only classifier cannot see the image evidence. OCR brings recognized in-image wording into the text branch, while the image branch can add layout and visual signals that OCR does not preserve. The implemented text-only arm includes OCR, so it must be distinguished from a caption-only baseline when evaluating this premise.

Research premise

The earlier source investigation found examples of impersonated public figures promoting investment platforms. Such examples motivate combining image and text evidence. Demonstrating the benefit still requires a controlled ablation on reviewed data, including cases with a benign caption and an image-carried claim. The repository does not supply that evaluation result.

02System design

Layered by pipeline stage, with one shared data contract.

The system is organised as a staged pipeline. Collection resumes by UID and enrichment/OCR cache results; curation and splitting regenerate outputs. Pass stage-specific input paths to preserve enrichment between stages. Every stage speaks the same record type, so adding a source or an encoder never requires touching the stages around it.

Repository layout

Why this shape

  • Stage numbering in scripts/ makes the execution order unambiguous. A new team member can read the directory listing and know what runs when.
  • One package, layered by stage rather than by file type. Adding an OCR backend touches one directory; adding a source touches one directory.
  • Installable via pyproject.toml, so imports are real imports rather than sys.path manipulation. The base install supports collection without torch; optional extras ([ocr], [model], [graph], [serve], [frontend]) add the dependencies needed for later work.
  • Config over constants. Core sources, architecture, training seeds and split ratios live in configuration. Record the checkpoint threshold and frontend preprocessing alongside that configuration when reporting a result.
  • Thin scripts, thick library. Most pipeline logic sits in src/fipd/; stage CLIs handle arguments and reports. The standalone AMFI collector and frontend also contain application logic.

Research workbench deployed at promotion-lens-demo.streamlit.app. Hosting does not validate the detector.

Image analysis

app.py accepts JPG, PNG and WebP images up to 10 MB and 12 million pixels, plus an optional original caption. Four selectable examples use the 11 tracked demonstration images; they are not a held-out benchmark. The hosting upload widget allows 50 MB for media, while image analysis separately enforces its smaller limit.

  • Extract text: default English/Hindi OCR and descriptive wording cues; no classifier checkpoint is required.
  • Pilot demo: explicit local opt-in to a tiny randomly initialized engineering model trained on 14 provisionally AI-labelled images. Outputs are unvalidated.
  • Research model: requires a compatible student/fused checkpoint at data/checkpoints/fused_seed42.pt, a validation-selected threshold, architecture/text/input-pipeline provenance, and matching local tokenizer/encoder assets. Legacy metadata-free and pilot checkpoints are rejected.

Resources initialize on analysis, not preview. Results persist until inputs or settings change. EXIF orientation and alpha compositing are consistent between preview and analysis. JSON exports retain evidence and timing. Class scores are not calibrated authenticity guarantees, regulator approval or investment advice.

Design change from this investigation

Some fact-check publishers provide schema.org ClaimReview markup — structured data used to describe reviewed claims. The collection code can also query the Google Fact Check Tools API when a key is configured. That provides a cross-publisher discovery route: one query surface returning claim text, the publisher's own verdict, language and URL across every publisher at once, instead of five HTML parsers that break on redesign.

The API also supports reviewPublisherSiteFilter, so collection runs a publisher sweep across nine Indian fact-checkers — pulling entire archives and letting the finance filter narrow them — before falling back to a keyword sweep. That does not depend on our lexicon matching their headline wording, which materially raises recall.

06Design decisions

Each one had a plausible alternative. Stating what was rejected, and why, is the defensible form.

Google Fact Check API as the primary discovery layer

Rejected
Crawling each fact-checker's HTML independently.
Why
Five HTML parsers means five things that silently break on redesign. ClaimReview is a standard publishers maintain themselves, because their Google visibility depends on it — a strong incentive for accuracy, which is exactly what you want in a label source.
Cost
The API returns no images. Stage 02 exists to fetch them.

"Misleading" maps to FAKE, not to a third class

Rejected
A three-class problem: true / misleading / false.
Why
A truncated-axis chart is factually "partly true" and is still a fraudulent promotion. For a fraud detector the operative question is does this deceive, not is every pixel false. Binary also keeps class counts usable at the sizes this dataset will reach.
Unresolved
Verdicts that cannot be placed map to unknown and are held out of training rather than guessed at — guessing injects label noise no model capacity recovers from.

Finance relevance is a hand-weighted lexicon, not a classifier

Rejected
Training a small text classifier to identify finance content.
Why
At collection time there are no labels to train it on — the argument is circular. And a transparent rule can be inspected, tuned and defended in a viva.
How
Terms weighted 3.0 / 1.5 / 0.7; fields multiplied (title ×2.5, claim ×2.0, image text ×1.5, body ×1.0). A headline term counts far more than a passing mention in paragraph nine.
Key part
The negative lexicon. Political stories say "crore", "scam" and "fraud" constantly. Terms like communal, election, temple subtract from the score. In testing, a communal-riot article mentioning "crores of views" scored −4.0 against a keep threshold of 4.0, while a genuine SEBI trading-app scam scored 70.15.
Scripts
English, Devanagari (निवेश घोटाला) and romanised Hinglish (paisa double) — scam creatives routinely use Latin-script Hindi, and a Devanagari-only lexicon would miss them entirely.

Three perceptual hashes, not one

Problem
Exact SHA-256 hashing does not find duplicates: each fact-checker re-hosts the creative through its own CDN, which re-encodes and often re-crops it.
Built
pHash (low-frequency DCT, most robust to compression), dHash (brightness gradients, robust to rescaling), cHash (colour block signature). Combined into one weighted normalised distance.
Why colour
pHash and dHash both work on greyscale and are blind to colour. Two creatives from the same template with different branding collide under both. Scam creatives are mass-produced from templates, so this is a live failure mode — it was found by a test, not anticipated.
Threshold
Deliberately not hardcoded from synthetic data. scripts/calibrate_dedup.py estimates it from the real corpus. The shipped default is a starting point, and this is stated in the code.

Over-merging is the safe direction

Insight
The two dedup failure modes are not symmetric.
Over-merge
Two distinct items land in one cluster. Costs a little data diversity. Cannot cause leakage.
Under-merge
Duplicates land in different clusters, the same creative appears in train and test, and every metric is silently inflated.
Therefore
The clustering default errs liberal; pick_canonical uses a stricter threshold, because there the asymmetry runs the other way.

Split by claim cluster, never by record

Why
This is the most common silent failure in misinformation-detection work, and it is invisible in the metrics: leakage makes results better, so nothing looks wrong.
Defence
verify_no_leakage asserts every cluster lives entirely in one split, stage 05 refuses to write the manifest if it fails, and the test suite injects deliberate leakage to confirm detection fires.
Also
Stratified by (label, source) so no split is accidentally single-publisher — otherwise the test set measures one newsroom's house style rather than fraud.
Reproducibility
Seeded RNG over sorted cluster ids. The manifest records the seed, counts and a hash; every result should cite that hash.

Image hygiene — the most likely source of a fake result

The trap
Fact-checkers stamp verdict graphics onto the images they debunk. If those enter training, the model learns to detect the watermark, not the fraud — and reports excellent accuracy while being worthless on real posts.
Defences
(1) URL blocklist for logos, avatars, share icons. (2) ImageAsset.role="annotated" tagging for suspected verdict stamps. (3) Extraction scoped to the article body, so sidebar thumbnails never enter. (4) OCR skips annotated images, so the word "FALSE" never reaches the text branch.
Insufficient
None of this replaces a manual spot-check before training. Stated in the README and the checklist.

OCR text goes first in the text input

Why
The claim being classified lives inside the image. When the tokeniser truncates at max length, it should eat the caption, not the thing we care about.
Also
Which fields are included (caption-only / OCR-only / both) is itself an ablation axis worth reporting.

Transliteration by curated lexicon, not blanket conversion

Problem
MuRIL was pretrained on Devanagari Hindi and English, but not on romanised Hindi at scale. "paisa double" tokenises into English-looking subwords carrying none of the Hindi meaning.
Rejected
Transliterating everything. Romanised Hindi has no standard orthography ("paisa"/"paise"/"paisaa"), and rule-based conversion of genuinely English words produces nonsense.
Built
A curated domain lexicon (~70 finance/scam terms) with optional library fallback. Both surface forms are kept by default — the encoder uses whichever it represents better, at the cost of sequence length only.

10Open problems

The main research blocker is a reviewed, diverse two-class corpus and credible held-out evaluation.

Data quality and source shortcuts

Review task relevance, original creatives/captions, class labels and OCR. Exclude fact-check verdict stamps and editorial screenshots from model inputs. Balance sources and creative styles across classes; add legitimate promotions, warnings/education as clearly distinguished hard negatives, and diverse scam campaigns. AMFI-only negatives can expose branding shortcuts. Official branding or broker registration alone does not verify every claim.

Text sanitation

configs/model.yaml already uses fields: [ocr_text, claim_text]; the editorial title field was removed in commit eb5d407. Original-caption provenance still needs review: archive claim text can contain verdict leakage or differ from a social caption. Other experimental configurations must be audited separately. Preserve annotation text for provenance outside the inference inputs.

Fair comparison and Gate 4

The runner now verifies a common multimodal cohort, seeds before model construction and isolates experiment outputs. Gate 4 requires manually reviewed held-out UIDs and uses the same full-test predictions without retraining. The text-only arm already includes OCR: a caption-only baseline and source/campaign-isolated evaluation are still needed. One fused win on a small subset is evidence to investigate, not proof of generalization.

Production artifacts and evaluation

Freeze reviewed group-aware splits with both classes, verify exact/near-duplicate and campaign isolation, then train and retain multi-seed artifacts. Evaluate misclassifications and confidence intervals before drawing performance conclusions. A validated compressed checkpoint, measured end-to-end memory/latency, calibrated scores and media-specific evaluation remain outstanding.
