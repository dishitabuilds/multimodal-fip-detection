# Image classification integration

The main Streamlit app defaults to `svm` (Classify promotion), with OCR-only mode
available separately. Older transformer checkpoint modes remain in the analysis
service for compatibility but are not main-app choices.

Root cause of the previous failures: the UI routed classification to unavailable
14-image or incompatible transformer checkpoints, although the presentation's
47-image experiment uses a joblib TF-IDF/MobileNet/LinearSVC artifact.

`analysis._load_svm_classifier` validates bundle manifest hashes before joblib
loading, then validates experiment `visual-source-holdout-20261113`, split counts,
cohort, text settings and matching image weights. It reuses classical.py's fitted
preprocessing and inference without retraining or downloads. Runtime metadata
does not initialize models. Streamlit caches resources with all bundle-file stamps;
input/mode/model changes invalidate the previous result.

The result contains a binary label, signed decision margin, experiment ID and
artifact hash. `class_scores` stays null for the SVM: margins are not probabilities.
The 47-image model remains a preliminary pilot, not investment-safety certification.

Phishing reward messages are outside this financial-promotion cohort. Real uploads
on 2026-11-22 returned negative margins despite visible reward/claim or QR prompts.
The analysis now abstains from a Real/Fake verdict when OCR finds reward wording
plus an action prompt without investment context. It preserves the raw SVM label
and margin in model details and displays a phishing review warning. This guard is
an explicit scope check, not retraining or a validated phishing classifier.

Regression coverage: tests/test_svm_frontend.py, tests/test_frontend.py and
tests/test_svm_integration.py. The integration test uses real OCR and saved model
assets through Streamlit AppTest; only the upload transport is simulated.
